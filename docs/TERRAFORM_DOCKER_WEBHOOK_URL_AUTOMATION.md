# WEBHOOK_URL Automation in Terraform & Docker

## Overview
WEBHOOK_URL is now automatically configured in Terraform infrastructure and Docker setup, ensuring webhooks always register correctly.

## Architecture

### 1. Terraform User Data Script
**File:** `terraform/n8n-infrastructure/user-data.sh`

**What it does:**
- Creates `/opt/n8n/.env` with WEBHOOK_URL during instance boot
- Generates `docker-compose.yml` for container management
- Creates `/usr/local/bin/restart-n8n.sh` for safe restarts
- Ensures Docker container always uses `--env-file` flag

**Key Configuration:**
```bash
# .env file created with:
WEBHOOK_URL=https://${n8n_domain}
N8N_PROTOCOL=https
N8N_HOST=${n8n_domain}
N8N_PORT=5678
```

### 2. Docker Compose Configuration
**File:** `terraform/n8n-infrastructure/docker-compose.yml` (generated by user-data)

**What it does:**
- Uses `env_file: /opt/n8n/.env` (automatic --env-file)
- Explicitly sets WEBHOOK_URL in environment (redundant but ensures it)
- Includes health checks
- Proper volume mounts

**Key Features:**
```yaml
env_file:
  - /opt/n8n/.env
environment:
  - WEBHOOK_URL=https://${n8n_domain}  # Explicit override
```

### 3. Restart Script
**File:** `/usr/local/bin/restart-n8n.sh` (created by user-data)

**What it does:**
- Ensures container is always restarted with --env-file
- Can be called manually or via systemd/cron
- Verifies WEBHOOK_URL is set after restart

## Deployment

### New Infrastructure (Terraform Apply)
```bash
cd terraform/n8n-infrastructure
terraform init
terraform plan
terraform apply
```

WEBHOOK_URL will be automatically configured during instance creation.

### Existing Infrastructure

**Option 1: Update via Terraform**
```bash
cd terraform/n8n-infrastructure
terraform apply
# This will update user-data (requires instance replacement or manual update)
```

**Option 2: Manual Update (Faster)**
```bash
# Copy updated scripts to EC2
scp terraform/n8n-infrastructure/user-data.sh ubuntu@n8n.pbradygeorgen.com:/tmp/
scp terraform/n8n-infrastructure/docker-compose.yml ubuntu@n8n.pbradygeorgen.com:/opt/n8n/

# On EC2, run:
sudo bash /tmp/user-data.sh  # (selective parts)
# OR manually:
sudo /usr/local/bin/restart-n8n.sh
```

**Option 3: Use Existing Scripts**
```bash
# We have automated scripts that do this:
node scripts/restart-n8n-docker-with-env.js
```

## Verification

### Check WEBHOOK_URL is Set
```bash
# On EC2
sudo docker exec n8n env | grep WEBHOOK_URL
# Should output: WEBHOOK_URL=https://n8n.pbradygeorgen.com
```

### Check n8n Settings API
```bash
curl -s "https://n8n.pbradygeorgen.com/rest/settings" \
  -H "X-N8N-API-KEY: YOUR_KEY" | jq '.webhookUrl'
# Should output: "https://n8n.pbradygeorgen.com"
```

### Test Webhook Registration
```bash
# Activate a workflow with webhook trigger
# Wait 30 seconds
curl -X POST "https://n8n.pbradygeorgen.com/webhook/knowledge-ingest" \
  -H "Content-Type: application/json" \
  -d '{"test": true}'
# Should return 200 (not 404)
```

## Maintenance

### Updating WEBHOOK_URL
If domain changes, update:
1. **Terraform variable:** `n8n_domain` in `terraform.tfvars`
2. **On EC2:** Edit `/opt/n8n/.env` and restart:
   ```bash
   sudo nano /opt/n8n/.env  # Update WEBHOOK_URL
   sudo /usr/local/bin/restart-n8n.sh
   ```

### Restarting n8n
Always use the restart script to ensure WEBHOOK_URL is maintained:
```bash
sudo /usr/local/bin/restart-n8n.sh
```

## Troubleshooting

### WEBHOOK_URL Still Null After Deployment
1. Check container environment: `docker exec n8n env | grep WEBHOOK_URL`
2. Check .env file: `cat /opt/n8n/.env | grep WEBHOOK_URL`
3. Restart with script: `sudo /usr/local/bin/restart-n8n.sh`
4. Check n8n logs: `docker logs n8n | grep -i webhook`

### Container Not Using --env-file
1. Verify docker-compose.yml exists: `ls -la /opt/n8n/docker-compose.yml`
2. Check docker-compose is used: `docker ps --format "{{.Names}}" | grep n8n`
3. Manually restart: `cd /opt/n8n && docker-compose restart`
