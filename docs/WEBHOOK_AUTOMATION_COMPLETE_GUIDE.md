The automation tries methods in this order:

1. **AWS SSM (Systems Manager)** - Most automated, no SSH keys needed
2. **SSH** - Requires SSH key and access
3. **Manual Instructions** - Fallback if automation fails

## 🔧 Automation Methods

### Method 1: AWS SSM (Recommended)

**Script:** `scripts/fix-n8n-webhooks-automated.sh`

**Requirements:**
- AWS credentials configured
- EC2 instance has SSM agent running
- IAM permissions for `ssm:SendCommand`, `ssm:GetCommandInvocation`

**How it works:**
1. Creates configuration script
2. Sends command to EC2 via AWS SSM
3. Sets `WEBHOOK_URL` in `/opt/n8n/.env`
4. Restarts n8n (systemd or Docker)
5. Verifies webhook registration

**Usage:**
```bash
bash scripts/fix-n8n-webhooks-automated.sh
```

### Method 2: SSH

**Script:** `scripts/fix-n8n-webhook-url.sh`

**Requirements:**
- SSH key file exists (default: `~/.ssh/AlexKeyPair.pem`)
- SSH access to EC2 instance
- Security group allows SSH from your IP

**How it works:**
1. Connects to EC2 via SSH
2. Sets `WEBHOOK_URL` in `/opt/n8n/.env`
3. Restarts n8n
4. Verifies configuration

**Usage:**
```bash
bash scripts/fix-n8n-webhook-url.sh
```

### Method 3: Manual (Fallback)

If automation fails, follow the manual instructions generated by the script.

**Location:** `.backup-ec2-emergency/MANUAL_WEBHOOK_SETUP_INSTRUCTIONS.md`

## 🐛 Troubleshooting

### Issue: AWS SSM Not Available

**Symptoms:**
- Script fails with "SSM agent not fully configured"
- Command ID is "None" or empty

**Solutions:**
1. **Check SSM Agent:**
   ```bash
   aws ssm describe-instance-information --instance-ids i-xxxxx
   ```

2. **Install SSM Agent (if missing):**
   - Connect to EC2 via AWS Console
   - Run: `sudo snap install amazon-ssm-agent`
   - Or use EC2 Instance Connect

3. **Use SSH Method:**
   ```bash
   bash scripts/fix-n8n-webhook-url.sh
   ```

### Issue: SSH Connection Failed

**Symptoms:**
- "Connection refused" or "Permission denied"
- SSH key not found

**Solutions:**
1. **Check SSH Key:**
   ```bash
   ls -la ~/.ssh/AlexKeyPair.pem
   chmod 400 ~/.ssh/AlexKeyPair.pem
   ```

2. **Test SSH Connection:**
   ```bash
   ssh -i ~/.ssh/AlexKeyPair.pem ubuntu@n8n.pbradygeorgen.com
   ```

3. **Check Security Group:**
   - Ensure port 22 is open from your IP
   - Check EC2 instance security group rules

### Issue: Webhook Still Returns 404

**Symptoms:**
- `WEBHOOK_URL` is set correctly
- n8n restarted
- Webhook still returns 404

**Solutions:**
1. **Verify WEBHOOK_URL in Container:**
   ```bash
   # Via SSH
   docker exec n8n env | grep WEBHOOK_URL
   
   # Should show: WEBHOOK_URL=https://n8n.pbradygeorgen.com
   ```

2. **Check n8n Settings:**
   ```bash
   curl https://n8n.pbradygeorgen.com/rest/settings \
     -H "X-N8N-API-KEY: your-key" | jq '.webhookUrl'
   ```

3. **Manual Toggle Workflow:**
   - Visit: https://n8n.pbradygeorgen.com
   - Find workflow: "Knowledge Ingest (Crew Memories => Supabase RAG)"
   - Toggle: OFF → wait 2s → ON

4. **Wait Longer:**
   - n8n may need 30-60 seconds to fully register webhooks
   - Re-run verification after waiting

### Issue: Workflow Activation Fails

**Symptoms:**
- API returns 401 (Unauthorized)
- API returns 404 (Not Found)

**Solutions:**
1. **Check API Key:**
   ```bash
   grep N8N_API_KEY ~/.zshrc
   # Or
   grep N8N_OWNER_API_KEY ~/.zshrc
   ```

2. **Use Correct Endpoint:**
   - Deactivate: `POST /api/v1/workflows/{id}/deactivate`
   - Activate: `POST /api/v1/workflows/{id}/activate`
   - Not: `PATCH /api/v1/workflows/{id}`

3. **Verify Workflow Exists:**
   ```bash
   node scripts/list-all-n8n-workflows.js | grep "Knowledge Ingest"
   ```
